# otorithm.com

Static, multi-page website for Otorithm. No framework and no npm: a small Python script turns
`content.py` into plain HTML pages, served by Nginx in Docker.

## Edit and preview

```bash
# edit copy in content.py (styles in assets/styles.css)
python3 build.py                                  # writes dist/
python3 -m http.server 8080 --directory dist      # http://localhost:8080
```

## Pages

| Page | File |
|---|---|
| Home | `index.html` |
| Services overview + 6 service pages | `services.html`, `services/*.html` |
| Industries | `industries.html` |
| Approach (delivery loop, models, security, time zones) | `approach.html` |
| Work (engagement blueprints) | `work.html` |
| Insights + 3 articles | `insights.html`, `insights/*.html` |
| About, Careers, Contact, Privacy, 404 | `about.html` … `404.html` |

Every page also gets a Markdown twin (`about.md`, `services/staff-augmentation.md`, `index.md` for
the home page), and the build writes `sitemap.xml`, `robots.txt`, `llms.txt`, `llms-full.txt`,
`insights/feed.xml`, `manifest.json`, `.well-known/security.txt` and the IndexNow key file. See
[Search engines and AI assistants](#search-engines-and-ai-assistants).

## Before launch

- `SITE['form_endpoint']` in `content.py`: set a form backend URL (Formspree, Basin or your own API)
  so the contact form posts. Left empty, the form composes the message for the visitor to email.
- Create the contact@ and careers@ mailboxes.
- Check every claim in `content.py` against how you actually operate (timelines, security practices,
  response times, open roles).
- Add the LinkedIn company page URL to `SITE['same_as']` in `content.py`: it appears in the footer
  and in the structured data that ties the site to the company.

## Hero video

`assets/hero.mp4` is a generated placeholder. To use an AI-generated clip, follow
`tools/ai-video-prompts.md`, then run `tools/prepare_hero_video.sh clip.mp4 pingpong` and rebuild.

## Deploy (Docker on the VPS)

The `Dockerfile` runs `build.py` in a Python stage and copies `dist/` into `nginx:alpine`.
`deploy/` holds compose files for Traefik, Nginx Proxy Manager, Caddy or host Nginx, and
`.github/workflows/deploy.yml` builds the image on every push to `main`, publishes it to
`ghcr.io/jayeshnair/otorithm-web`, and restarts it on the VPS once these repository secrets exist
(Settings → Secrets and variables → Actions):

- `VPS_HOST`: the VPS IP address
- `VPS_SSH_KEY`: a private key for the `deploy` user on the VPS

Until the secrets are set, the workflow builds and publishes the image and skips the VPS step.

```bash
docker build -t otorithm-web .
docker run --rm -p 8080:80 otorithm-web      # http://localhost:8080
```

## Search engines and AI assistants

The site is built to be found by search engines (SEO), quoted by answer engines such as Google's AI
Overviews (AEO), and read and cited by AI assistants such as ChatGPT, Claude, Perplexity and Gemini (GEO).
All of it is generated by `build.py` from `content.py`, so it stays in step with the copy.

| What | Where | Why |
|---|---|---|
| Titles and descriptions sized for results pages | `pages()` in `build.py`, `seo_title` / `seo_desc` per service | The build fails if a title passes 70 characters or a description 160 |
| Structured data (JSON-LD `@graph`) | every page | Organization, WebSite, WebPage, BreadcrumbList, Service, FAQPage and BlogPosting, linked by `@id` |
| FAQs in plain HTML | home page, every service page | Question-and-answer text that answer engines quote, marked up as `FAQPage` |
| Share images (1200 × 630) | `assets/og/` | Link previews on LinkedIn, X, Slack and WhatsApp; one per service and article |
| Markdown twin of every page | `<page>.md`, linked with `rel="alternate"` | Clean text for LLM crawlers; served with a canonical `Link` header back to the HTML page |
| `llms.txt`, `llms-full.txt` | site root | A summary and index of the site for AI assistants, and the whole site in one file |
| `robots.txt` | site root | Allows search engines and AI crawlers by name, with `Content-Signal` allowing search, AI answers and training |
| `sitemap.xml` with `lastmod` | site root | Dates come from `lastmod.json` and change only when a page's content changes |
| IndexNow | `SITE['indexnow_key']`, `tools/indexnow.py`, deploy workflow | Bing and other IndexNow engines recrawl changed pages within minutes of a deploy |
| Article dates and key takeaways | `ARTICLES` in `content.py` | Freshness signals and quotable summaries |
| Self-hosted Sora font, preloaded hero poster | `assets/fonts/`, `page_home` | Faster first paint (Core Web Vitals) and no third-party font requests |
| One URL per page | `docker/nginx.conf` | `/services` and `/services/` redirect to `/services.html`; `/index.html` redirects to `/` |

### When you change things

- **Edit copy:** run `python3 build.py` and commit `lastmod.json` along with `content.py`, so the
  sitemap dates reflect real changes.
- **Rename a service, add an article or change the brand mark:** re-render the share images and icons
  with `python3 tools/make_social_images.py` (needs Playwright), then rebuild.
- **Add an article:** give it `published`, `updated`, `takeaways` and `keywords`, like the others.

### One-time setup after launch

1. **Google Search Console:** add the domain property for otorithm.com (DNS verification at GoDaddy,
   or paste the HTML-tag code into `SITE['verification']['google']`), then submit
   `https://otorithm.com/sitemap.xml`.
2. **Bing Webmaster Tools:** import the site from Search Console (or paste its code into
   `SITE['verification']['bing']`) and submit the sitemap. Bing's index also powers ChatGPT search and Copilot.
3. **LinkedIn and other profiles:** add their URLs to `SITE['same_as']`.
4. **If a CDN such as Cloudflare is ever put in front of the site,** check that its bot settings do not
   block AI crawlers, which some CDNs do by default.
5. **Check the structured data** with Google's Rich Results Test and the Schema.org validator.
